# Развёртывание стенда

Весь тренажёр поднимается одной командой на чистой ВМ:

```bash
deploy/up.sh
```

Зачем отдельный стенд, а не ноутбук с туннелем: по правилам сдачи
прототип должен открываться по ссылке всё время экспертизы — это
несколько дней, — а после стоп-кода (29.09, 23:59 МСК) обновлять его
запрещено. Стенд должен работать сам, переживать перезагрузки и не
требовать человека.

## Что поднимается

```
            ВМ, HTTPS — порт WEB_TLS_PORT (443), 80 переадресует
                    │
                ┌───▼───┐  статика клиента
                │  web  │  /api/* и /ws → backend
                └───┬───┘
                    │ внутренняя сеть compose
              ┌─────▼─────┐        ┌───────┐
              │  backend  │───────▶│ model │  llama.cpp + GigaChat 3.1
              └─────┬─────┘  8090  └───────┘  (только если есть веса)
                    │   │    8091  ┌───────┐
                    │   └─────────▶│ voice │  GigaAM v3 + TeraTTSv2
                    │              └───────┘  (только если есть веса)
                    │ 5432
                ┌───▼───┐
                │  db   │  PostgreSQL 16
                └───────┘
```

| Сервис | Что это | Наружу | Тома |
|---|---|---|---|
| `web` | nginx: собранный клиент, прокси на сервер, HTTPS | `WEB_TLS_PORT` (443), `WEB_PORT` (80 → 443) | — |
| `backend` | сервер тренажёра, release-сборка | нет | `backups` — ежесуточные копии базы |
| `db` | PostgreSQL 16 | нет | `db-data` |
| `model` | llama.cpp с нашим патчем MTP | нет | каталог весов с ВМ, только чтение |
| `voice` | распознавание и синтез речи на процессоре | нет | каталог весов голоса, только чтение; `voice-cache` — синтезированные фразы |
| `nli` | кросс-энкодер OpenJEV: сверка описания курсанта с фактами вызова | нет | каталог чекпоинта, только чтение |

Наружу открыт один порт. Сервер, база и модель видны только внутри
сети compose.

При первом запуске сервер сам накатывает миграции (в них и учебные
учётные записи) и импортирует классификатор из `task/*.xlsx`. Опросные
карты для типов, которых нет на скриншотах боевой системы, выводятся
из классификатора при каждом старте.

**Модель необязательна.** `up.sh` включает её, только если находит
файл весов. Без него сервер работает с `ML_PROVIDER=mock`: классификация,
оценка, журнал, карточки, занятия, прогноз — всё работает, нет только
ответов модели при подготовке и правке учебных вызовов и словесной
сводки по группе.

**Голос необязателен.** `up.sh` поднимает его, только если находит
веса в `VOICE_DIR`. Без голоса диспетчер говорит со старшим бригады
текстом — кнопки «Сказать голосом» просто нет.

**Кросс-энкодер необязателен.** `up.sh` поднимает его, только если
находит чекпоинт в `NLI_DIR`. Без него описание курсанта сверяет
языковая модель — медленнее и, на процессоре, хуже видит упущенное.
Память: чекпоинт 2B — около 9 ГБ; вместе с моделью (около 7 ГБ) это
укладывается в 32 ГБ.

## Требования к ВМ

| | Минимум | Почему |
|---|---|---|
| Процессор | 6 ядер x86-64 | замер модели 14,8 ток/с сделан на шести потоках |
| Память | 16 ГБ без модели, **32 ГБ с моделью** | веса 6,45 ГБ плюс контекст |
| Диск | **40 ГБ** | готовые образы ~1 ГБ, но сборка тянет базовые образы Rust и Node и кэш — ещё ~6 ГБ; сервер модели ~2 ГБ; веса 6,5 ГБ; база и копии |
| ОС | Ubuntu 22.04 или 24.04 | |
| Видеокарта | не нужна | всё на процессоре |

В Yandex Cloud: **не прерываемая** ВМ (прерываемые останавливаются
не реже раза в сутки — ссылка у экспертов перестанет открываться)
и **статический** публичный адрес (динамический меняется при перезапуске
ВМ, и ссылка в форме сдачи станет недействительной).

## Шаги

### 1. Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
# перелогиниться, чтобы группа применилась
docker compose version        # нужна 2.20 или новее
```

### 2. Код

Разворачивать лучше тот коммит, что сдаётся, — по метке. Тогда стенд
гарантированно совпадает с репозиторием на момент стоп-кода:

```bash
git clone https://github.com/Den4ikAI/arm112-trainer.git
cd arm112-trainer
git checkout <метка-сдачи>
```

### 3. Веса модели (если нужна модель)

Файл собран своей конвертацией — в опубликованном GGUF блока MTP нет,
поэтому скачать его неоткуда, только скопировать. На ВМ:

```bash
sudo mkdir -p /opt/arm112/model && sudo chown "$USER" /opt/arm112/model
```

С машины, где лежат веса:

```bash
rsync -avP /путь/к/full-mtp-q4_K_M.gguf \
  <пользователь>@<адрес-ВМ>:/opt/arm112/model/
```

6,45 ГБ: на канале 100 Мбит/с это около десяти минут.

Каталог и имя файла задаются в `deploy/.env` (`MODEL_DIR`, `MODEL_FILE`).

Модель уже развёрнута на другой машине контура? Шаг не нужен: укажите
её адрес в `deploy/.env` — `ML_BASE_URL=http://адрес:порт` (сервер,
совместимый с OpenAI API). `up.sh` тогда не поднимает свой контейнер
модели.

### 3а. Веса голоса (если нужен голос)

Обе модели — ONNX, работают на процессоре. Около 2 ГБ. На ВМ:

```bash
sudo mkdir -p /opt/arm112/voice && sudo chown "$USER" /opt/arm112/voice
pip install huggingface_hub
python3 - <<'EOF'
from huggingface_hub import snapshot_download
snapshot_download('istupakov/gigaam-v3-onnx', local_dir='/opt/arm112/voice/gigaam-v3-onnx',
                  allow_patterns=['*e2e_rnnt*', 'config.json', 'LICENSE.txt'])
snapshot_download('TeraSpace/TeraTTSv2', local_dir='/opt/arm112/voice/TeraTTSv2')
EOF
```

ВМ без интернета — скачать там, где он есть, и скопировать каталог
`rsync`-ом, как веса модели. Каталог задаётся в `deploy/.env`
(`VOICE_DIR`), потоки — `VOICE_THREADS` (4 по умолчанию: ядра делятся
с моделью и сервером). Замер — `backend/docs/замеры/ГОЛОС.md`.

### 3а'. Веса кросс-энкодера (сверка описания на процессоре)

Кросс-энкодер OpenJEV сверяет описание курсанта с фактами вызова за
секунды и точнее языковой модели на процессоре
(`backend/docs/замеры/ОПИСАНИЯ.md`). Чекпоинт 2B — 4,2 ГБ на диске,
около 9 ГБ памяти; 4B — 8,5 ГБ и около 18 ГБ памяти.

```bash
sudo mkdir -p /opt/arm112/nli && sudo chown "$USER" /opt/arm112/nli
python3 - <<'EOF'
from huggingface_hub import snapshot_download
snapshot_download('AlexWortega/openjev', local_dir='/opt/arm112/nli',
                  allow_patterns=['qwen3.5-2b-nli-v5/*'])
EOF
```

Чекпоинт выбирается в `deploy/.env` (`NLI_MODEL`), каталог — `NLI_DIR`.
Нет каталога — `up.sh` кросс-энкодер не поднимает, и описание сверяет
языковая модель. Выбрать движок вручную можно настройкой
`analysis.engine` в администрировании (0 — авто, 1 — кросс-энкодер,
2 — языковая модель).

### 3б. Профиль GPU (если есть видеокарта)

Тот же тренажёр, другая модель: Gemma 4 26B-A4B (INT4) в vLLM на одной
RTX 4090. Отдельной сборки тренажёра нет — меняется только адрес модели.

```bash
pip install vllm==0.30.0          # на драйвере CUDA 12.x — сборка +cu129 с GitHub
huggingface-cli download cyankiwi/gemma-4-26B-A4B-it-qat-AWQ-INT4 --local-dir /opt/arm112/gemma
MODEL_DIR=/opt/arm112/gemma deploy/gpu/start-vllm.sh    # порт 8091
```

Вместо Gemma годится и Qwen3.8-27B (`RedHatAI/Qwen3.8-27B-INT4`) — он
втрое медленнее при том же качестве, сравнение — в документации, 6.2а.

В `deploy/.env`: `ML_BASE_URL=http://<машина с GPU>:8091`. Почему такие
флаги — в комментарии к `deploy/gpu/start-vllm.sh`. На GPU стоит
включить модель в каждой реплике начальника: настройка
`chief.live_model = 1` (на процессоре она выключена — реплика шла бы
десятки секунд).

Замеры на RTX 4090 — `docs/СОПРОВОДИТЕЛЬНАЯ-ДОКУМЕНТАЦИЯ.md`, раздел о
профилях.

### 4. Запуск

```bash
deploy/up.sh
```

При первом запуске скрипт создаёт `deploy/.env` со случайными паролем
базы и ключом подписи токенов, собирает образы и ждёт, пока сервер
ответит. В конце печатает адрес.

Первая сборка идёт долго, на 6 ядрах примерно:

| Что | Время |
|---|---|
| сервер (Rust, release) | 10–15 мин |
| сервер модели (llama.cpp) | 5–10 мин |
| клиент | 1–2 мин |
| загрузка весов в память при старте модели | около минуты |

Повторный `up.sh` пересобирает только то, что изменилось.

### 5. Порт

Открыть входящие TCP 443 и 80 (или `WEB_TLS_PORT` и `WEB_PORT`) в группе
безопасности облака или в `ufw`.

**Почему HTTPS.** Микрофон браузер даёт только защищённой странице: по
`http://адрес` голосовой ввод недоступен совсем, кнопка микрофона
неактивна и объясняет почему. `up.sh` при первом запуске выпускает
самоподписанный сертификат на адрес машины (`deploy/tls/`, в git не
кладётся) — браузер один раз предупредит, и дальше всё работает. Свой
сертификат — положить в `deploy/tls/cert.pem` и `key.pem` до запуска;
имя машины для сертификата можно задать `TLS_HOST=…`.

### 6. Проверка

```bash
deploy/check.sh                                 # на самой ВМ
deploy/check.sh https://<адрес>                 # с другой машины — как увидит эксперт
docker compose -f deploy/docker-compose.yml ps  # все сервисы healthy
```

`check.sh` ничего не меняет: входит учебной учётной записью и проверяет
клиент, сервер, журнал, учебные вызовы, загруженный классификатор,
канал событий через nginx, описание API и подключена ли модель.

### 7. Учебный набор

Чистый стенд наполняется учебным набором: 20 вызовов 112 и 20
происшествий ДДС по 10 темам, 2 группы операторов 112 и 2 группы
диспетчеров ДДС по 5 человек, по 2 экзамена и 2 тренировки по частям
на роль (созданы, никому не выданы). Скрипт **очищает учебные данные**
(карточки, вызовы, занятия, попытки, группы, учётные записи, кроме
администратора), поэтому сначала — копия базы:

```bash
cd deploy
docker compose exec -T db pg_dump -U arm112 -Fc arm112 > ../arm112-до-набора.dump
ARM112_DB_CONTAINER=deploy-db-1 python3 seed/залить.py https://127.0.0.1 arm112
```

`залить.py` ходит в API как преподаватель (вызовы и происшествия
создаются и утверждаются тем же путём, что в интерфейсе) и в базу через
`docker exec` — учётные записи и группы. Что внутри набора и откуда —
`docs/СОПРОВОДИТЕЛЬНАЯ-ДОКУМЕНТАЦИЯ.md`, раздел 4.10.

В браузере `https://<адрес>/` — вход. На демонстрационном стенде
задайте в `deploy/.env` `DEMO_PASSWORD` — пароль учебных учётных
записей, — и экран входа покажет их списком: вход одним щелчком.

| Логин | Роль |
|---|---|
| `admin` | администратор |
| `teacher1` | преподаватель — выдаёт вызовы и происшествия занятиями |
| `op01` … `op10` | операторы 112 (две группы по пять) |
| `dds01` … `dds05` | диспетчеры ДДС, группа 1: Служба 101, Служба 104, Служба 103, ЦОДД, Мослифт |
| `dds06` … `dds10` | диспетчеры ДДС, группа 2: Служба 101, Служба 104, Служба 103, ЦОДД, Деп. ЖКХ |

Без учебного набора — `admin`, `teacher1`, `student1`…`student5`.
Пароль у всех `arm112`. Описание API — `https://<адрес>/api/docs`.

## Эксплуатация

```bash
cd deploy
docker compose logs -f backend        # журнал сервера
docker compose logs -f model          # загрузка и работа модели
docker compose ps                     # состояние и health
docker compose restart backend        # перезапуск без пересборки
```

**Резервные копии.** Сервер раз в сутки делает `pg_dump` в том `backups`,
хранит `BACKUP_KEEP_DAYS` дней. Достать последнюю:

```bash
docker compose cp backend:/backups ./backups
```

**Перезагрузка ВМ.** Отдельно ничего делать не нужно: у всех сервисов
`restart: unless-stopped`, Docker на Ubuntu стартует вместе с системой.

## После стоп-кода — что НЕЛЬЗЯ

С 29.09, 23:59 МСК и до конца экспертизы оценивается ровно то, что
было на момент дедлайна. Правила хакатона: обновление стенда, накат
релизов и изменение функционала — **дисквалификация**, таймштампы
проверяются.

Нельзя:

- запускать `deploy/up.sh`, `docker compose up --build`, `docker compose pull`;
- делать `git pull`, `git checkout` или любые правки в каталоге репозитория на ВМ;
- менять `deploy/.env` (включая переключение модели) и файл весов;
- импортировать другую версию классификатора или переключать активную;
- удалять тома `db-data` и `backups`.

Можно:

- смотреть логи, `docker compose ps` и запускать `deploy/check.sh`;
- `docker compose restart <сервис>`, если сервис упал, — это перезапуск
  той же версии, а не обновление;
- то, что делают сами эксперты в интерфейсе: входить, заводить карточки,
  проводить занятия — это использование, а не изменение стенда.

Чтобы стенд не перезапустился сам посреди экспертизы из-за обновлений
ОС, на время оценки можно отключить автообновления:

```bash
sudo systemctl disable --now unattended-upgrades
```

## Если что-то не так

| Симптом | Что смотреть |
|---|---|
| `up.sh` ждёт и не дожидается | `docker compose logs backend` — обычно база ещё не поднялась или ошибка импорта классификатора |
| `ml_provider: "mock"` в health, хотя веса скопированы | путь `MODEL_DIR/MODEL_FILE` в `deploy/.env`; после исправления — `deploy/up.sh` (до стоп-кода!) |
| правка вызова перепиской падает по таймауту | модель ещё грузится: `docker compose logs model`, ждать `server is listening` |
| сервер пишет `password authentication failed` | поменяли `DB_PASSWORD` после первого запуска. PostgreSQL задаёт пароль один раз, при создании тома. Вернуть прежний пароль в `deploy/.env` — или, если данных не жалко, `docker compose down -v` и заново |
| нет места на диске | `docker builder prune -f` — кэш сборки занимает больше всего |
