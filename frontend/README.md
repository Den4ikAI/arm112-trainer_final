# Тренажёр АРМ-112 — фронтенд

Копия интерфейса боевой ПОВ-112 (система-112 Москвы) на **React**.
Доменный слой вынесен отдельным пакетом и не зависит от фреймворка.

```
frontend/
├── packages/
│   ├── domain/          доменный слой на TypeScript, без фреймворка
│   │   └── src/
│   │       ├── types.ts        модель карточки, адреса, статусов
│   │       ├── catalog.ts      типы происшествий, службы, опросные карты
│   │       ├── classifier.ts   движок эталона: признаки → тип → список служб
│   │       ├── response.ts     машина статусов реагирования ДДС
│   │       ├── scenarios.ts    учебные сценарии из билетов
│   │       └── scoring.ts      оценка: узнал / угадал / ошибся
│   └── styles/          токены и примеси SCSS
├── apps/
│   └── react/           React 19 + Vite + SCSS-модули
└── e2e/                 Playwright
```

## Запуск

```bash
npm run install:all    # зависимости приложения и тестов
npm run dev            # http://localhost:5173
npm run build          # production-сборка
npm test               # Playwright, сервер поднимается сам
npm run capture        # пересъёмка скриншотов
npm run check:domain   # проверки домена без браузера
```

## Архитектура

Приложение следует **FSD**:

| Слой | Что лежит | Где |
|---|---|---|
| `app` | роутер, провайдеры, глобальные стили | `src/app` |
| `pages` | экраны | `src/pages` |
| `widgets` | составные блоки интерфейса | `src/widgets` |
| `entities` | состояние предметной области (zustand) | `src/entities` |
| `shared` | UI-кит, утилиты | `src/shared` |

Зависимости идут строго вниз: `pages → widgets → entities → shared`.
Доменная логика не знает про React — она живёт в `packages/domain`
и импортируется как `@arm112/domain`.

## Стили

Один источник правды — `packages/styles`:

* `_tokens.scss` — палитра, снятая с пикселей боевого интерфейса,
  типографика, метрика. Всё через CSS custom properties.
* `_mixins.scss` — `field-label`, `underline-input`, `chip`, `thin-scroll`.
* `reset.scss` — нормализация.

Подключаются алиасом `@styles` из `vite.config.ts`.

Современный CSS используется там, где он даёт результат, а не ради галочки:
`color-mix()` в иллюстрации входа, логические свойства (`inset-inline`,
`padding-block`, `margin-inline`), `:has()`-free разметка ради совместимости,
контейнерная сетка на `grid-template-columns: repeat(12, …)`.

Тёмной темы нет намеренно: боевой АРМ работает в одном режиме, и тренажёр
должен совпадать с ним визуально, иначе теряется смысл узнаваемости.

## Что воспроизведено из боевой системы

Экраны и поведение сняты со скриншотов (`refs/СКРИНШОТ *.docx`) и описаны
в `../SCENARIOS.md`:

* **Вход** — форма с логином, паролем и номером АРМ, телефон техподдержки.
* **Журнал** — поиск, таблица происшествий с раскрытой строкой описания,
  тёмная панель часов, пагинация.
* **Карточка 112** — три блока телефонов, ФИО и статус заявителя,
  адресный блок на 15 полей, описание со счётчиком `0 / 1999`,
  блок «что случилось?» с плашками частых типов и поиском,
  опросные карты 101 / 104 / Взрыв / ДТП / БПЛА, оранжевая полоса служб,
  модалка «Добавьте службы».
* **Таймер** — краснеет при превышении норматива, порог 60 секунд
  (на скриншотах 00:44 тёмный, 01:03 красный).
* **Горячие клавиши** — Alt+T, Alt+A, Alt+O, Alt+S.
* **Карточка ДДС** — режим только для чтения, плашки служб со статусами,
  карандаш, строка ввода «Статус / Номер наряда / Комментарий», синяя
  панель истории.
* **Машина статусов** — последовательный выбор: сначала только
  «Принята» / «Не принята», комментарий обязателен для отказных статусов.

## Что добавлено сверх боевой системы

Это тренажёр, поэтому поверх точной копии лежит учебный слой:

* **Панель обучающегося** — легенда вызова, банк вопросов заявителю,
  лента разговора. Заявитель сообщает факт только в ответ на вопрос.
* **Разбор** — дифф с эталоном, где отдельно выделено «угадал»:
  значение верное, но заявитель его не сообщал. Это единственная метрика,
  которую нельзя получить, не сопоставив три слоя — скрытую истину сценария,
  стенограмму разговора и содержимое карточки.
* **Цена ошибки** вместо абстрактного балла: «служба не оповещена —
  фактически не выехала».

## Что нашли тесты

Playwright поймал три настоящих дефекта вёрстки, не видных на глаз:

1. **Панель обучающегося перекрывала рабочую область.** Была `position: fixed`
   в правом нижнем углу и накрывала выпадающий список типов происшествия —
   клик не доходил. Исправлено: панель стала третьей колонкой сетки,
   ниже 1400px уезжает под карточку.
2. **Всплывающая строка статуса ДДС обрезалась.** Контейнер плашек служб имел
   `overflow-x: auto`, из-за чего панель ввода статуса и история,
   позиционированные над плашкой, клиппировались, а клики перехватывала
   сама полоса. Исправлено: плашки переносятся по строкам без прокрутки.
3. **Горизонтальная прокрутка на 400px.** Пятиколоночная полоса телефонов
   не сжималась. Исправлено медиазапросом: ниже 900px блоки телефонов
   встают в колонку.

Отдельно тесты выявили ловушку в самих тестах: `getByText('Класс.:')`
попадал сразу в два элемента (обычный и `[ВИС] Класс.:`) — заменено
на `data-testid`.

## Проверка домена

`packages/domain/check.ts` — быстрые проверки без браузера:
правила классификатора (в том числе БПЛА → ЦУКБ Минобороны),
последовательность статусов реагирования и, главное, различение
«узнал» против «угадал»: одна и та же карточка получает разный балл
в зависимости от того, спросил ли курсант заявителя.

```bash
npm run check:domain
```
