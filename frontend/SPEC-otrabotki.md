# Отработки: регистрация исходящих звонков

Источник: `refs/Инструкция_по_заведению_карточки_2507ГСИ.docx`, раздел 11.3,
плюс рисунки 69–74 из той же инструкции.

**Оговорка про версию.** Кадры отработок датированы 2018–2019 годами
(в строках видно «27.07.18», «26.09.18»). Инструкция — неоднородный
источник, её карта 104 расходится со скриншотами 2026 года. Значит,
внешний вид отработок мог измениться, а свежих кадров у нас нет.
Структура полей при этом описана текстом инструкции и вряд ли поехала.

---

## Зачем это

Дословно из инструкции:

> Эта функция предназначена для регистрации звонков в службы, которые
> **не оповещены автоматически**.

То есть список оповещения формируется классификатором сам, а отработка —
это ручная регистрация того, что оператор кому-то дозвонился отдельно.

Кнопка «Добавить отработку» появляется **только после сохранения
карточки** и становится активной, когда заполнено хотя бы одно поле.

---

## Строка ввода

```
Опер. │ Дата и время   │ Служба        │ Куда звонили │ Телефон  │ ФИО      │ Суть сообщения │
  ✕   │ 27.07.18 10:40 │ [Служба 103 ▾]│ [куда]       │ [103] 📞 │ [Агапова]│ [отравление]   │ ✓
```

| Поле | Поведение |
|---|---|
| **Служба** | выпадающий список с поиском. **Произвольный текст ввести нельзя** |
| **Куда звонили** | свободный текст — для случая, когда службы нет в списке |
| **Телефон** | подставляется автоматически при выборе службы, можно ввести вручную |
| **ФИО** | фамилия или операторский номер того, кто принял звонок |
| **Суть сообщения** | итог дозвона |
| 📞 | кнопка вызова на указанный номер |
| ✓ | оранжевая галочка справа — сохранить строку. То же по Enter |
| ✕ | слева — отменить строку |

В тексте инструкции поле названо «Кто принял», а в интерфейсе колонка
подписана **«ФИО»**. Берём то, что на кадре.

## Сохранённая отработка

```
Опер.│ АРМ │ Дата и время        │ Служба     │Куда звонили│ Телефон │ ФИО       │ Суть сообщения
  0  │ 111 │ 26.09.18 11:25 11:27│ Служба 101 │            │ 101  📞 │ Филипенко │ Угроза взрыва
```

Отличия от строки ввода:

* появляются колонки **Опер.** и **АРМ** — кто и с какого места звонил;
* **две отметки времени** — по кадру похоже на начало и конец разговора;
* служебные колонки (Опер., АРМ, дата) залиты тёмно-бордовым — тот же
  цвет, что у колонки оператора в журнале происшествий;
* поля больше не редактируются.

Отработок может быть несколько, добавляются одна за другой.

---

## Что с этим делать нам

Заказчик на сессии вопросов и ответов подчеркнул, что в части телефонии
его интересует участок **B → C**: диспетчер ДДС дозванивается
до руководителей служб и бригад. Про объём: «для MVP достаточно
имитации звонков в базе».

Отработки — ближайший к этому механизм из существующих в боевой системе.

**Но есть нестыковка, которую надо держать в голове.** По инструкции
отработка описана в разделе «Работа с карточкой после сохранения»,
то есть это функция **оператора 112**, а не ДДС. На кадрах карточки ДДС
(`screenshots/reference/dds_*`) никаких отработок нет — там только
плашки служб со статусами.

Варианта два:

1. в боевой системе у ДДС отработок нет, и звонки в службы диспетчер
   фиксирует комментариями к статусам реагирования;
2. отработки есть и у ДДС, просто не попали в кадр.

Материалы ответа не дают. Вопрос занесён в `OPEN-QUESTIONS.md`.

**Что предлагается делать:** реализовать отработки как отдельный блок
карточки, доступный после сохранения, и показывать его в обоих режимах.
Для оператора 112 это прямо по инструкции, для ДДС — закрывает участок
B → C, на который указал заказчик. Если выяснится, что у ДДС этого нет,
блок убирается одним флагом.

## Соседний механизм: записи разговоров

Раздел 11.2 инструкции, рисунок в тех же материалах.

```
Записи разговоров
Опер.│ Дата и время     │ Телефон                        │Длительность│Скачать│Прослушать
     │ 11.06.2019 15:04 │ 79774038109, 24461 (Test IT2G 61)│   00:04   │   ⤓   │ ▶ плеер
                                                    ← вернуться в карточку
```

Плеер во всю ширину колонки, кнопка скачивания, длительность в мм:сс.
Если записей нет — «Записей не найдено».

Для нас это прямая подсказка, как показывать стенограмму и аудио
разговора на разборе: такой блок в боевой системе уже есть, и курсанту
он будет знаком.
