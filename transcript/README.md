# Рабочий диалог

Журнал разработки тренажёра оператора ДДС — от «изучи файлы» до
работающей системы.

| Файл | Что это | Размер |
|---|---|---|
| `dialog.md` | читаемый разговор: 71 реплика человека, 397 ответов | 412 КБ |
| `session.jsonl` | полный журнал сессии, включая вывод всех команд | 32 МБ |
| `render.py` | скрипт, который делает первое из второго | |

## Что вошло в `dialog.md`

Реплики человека, текст ответов и однострочные пометки о том, какие
инструменты вызывались. Результаты вызовов выброшены: их 32 МБ,
и читать это невозможно. Внутренние рассуждения модели не включены.

## Пересобрать

```bash
python3 render.py ~/.claude/projects/-media-denis-work4-lct-hack/<id>.jsonl dialog.md
```

## Зачем это здесь

В диалоге видно, как принимались решения и чем они обосновывались —
включая ошибки и то, как их находили. Несколько примеров:

* выбор Rust ради одного `.exe` вместо «ада из зависимостей»;
* «давай ка без выдумок обойдёмся» — после чего из проекта убрали
  сочинённые опросные карты и завели `PROVENANCE.md`;
* разбор чата с заказчиком, где я сначала неверно прочитал требование
  про телефонию, и меня поправили;
* гонка в стороже нормативов, найденная тестами: два экземпляра
  писали один переход в аудит дважды;
* `is_active` у версий классификатора, который никто никогда не
  выставлял — система работала на запасном «бери самую свежую»;
* замеры языковых моделей на профиле стенда, где первый вывод
  («модель не выполняет инструкции») оказался ошибкой замера,
  а не свойством модели.

Открытые вопросы, которые по ходу накопились, лежат отдельно —
`../OPEN-QUESTIONS.md`, их одиннадцать.
