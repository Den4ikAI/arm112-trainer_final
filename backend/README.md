# Бэкенд тренажёра АРМ-112

Rust + axum + PostgreSQL. Полная спецификация — `../BACKEND.md`.

## Запуск с нуля

```bash
docker compose up -d          # PostgreSQL на 5432
cp .env.example .env
cargo run                     # миграции накатятся сами
```

Проверка:

```bash
curl http://127.0.0.1:8080/api/admin/health
# {"db":true,"uptime_sec":5,"ml_provider":"mock","version":"0.1.0"}
```

Нужен Rust stable. Если не стоит:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

## Структура

```
src/
  main.rs       точка входа, сборка роутера
  config.rs     конфигурация из окружения
  error.rs      AppError → HTTP-коды из BACKEND.md §8.9
  state.rs      разделяемое состояние: пул БД, конфиг, адаптеры моделей
  api/          HTTP-хендлеры        ← по одному модулю на задачу
  domain/       классификатор, машина статусов, оценка
  ingest/       импорт классификатора из XLSX
  jobs/         фоновые задачи и очередь
  ml/           адаптеры моделей + заглушки
  store/        подключение к БД и миграции
  ws/           канал класса
  audit/        журнал действий
migrations/     SQL, накатываются при старте
```

## Модели

Ни один эндпоинт не зависит от модели напрямую — только от трейтов
в `ml/mod.rs`. Провайдер выбирается переменной:

```
ML_PROVIDER=mock   работает сейчас, система функциональна без моделей
ML_PROVIDER=onnx   появится в задаче про ONNX
ML_PROVIDER=http   внешний сервис моделей
```

Заглушки детерминированные: одинаковый вход даёт одинаковый выход,
иначе тесты плавают. Отдельно отмечу `MockLlm::group_insights` — он
**не выдумывает цифры**, а пересказывает настоящую агрегацию. Демо
выглядит честно, и при замене на модель контракт не меняется.

## Миграции

Имя файла: `<timestamp>_<описание>.sql`, где timestamp — **сплошное
число без разделителей**, например `20260920210003_scenarios.sql`.

Это не стиль, а требование sqlx: версией считается всё до первого `_`.
Если написать `20260920_2100_scenarios.sql`, версией станет `20260920`,
и все миграции получат одинаковый номер.

Чужие миграции **никогда не редактируем и не переименовываем** — только
добавляем свою следующую. Так двое разработчиков физически не столкнутся
в одном файле.

Накатить на чистую базу заново:

```bash
docker exec arm112-db psql -U arm112 -d arm112 \
  -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
cargo run
```

## Добавление своего роутера

В `api/mod.rs` добавьте строку **в конец** списка `.merge(...)`,
соседние не переставляйте. Git сливает добавления в разные места
без конфликта, а перестановки — нет.

```rust
.merge(health::routes())
.merge(auth::routes())   // ← ваша строка здесь
```
