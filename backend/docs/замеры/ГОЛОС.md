# Голос на процессоре: замер

28.09.2026. Скрипт — `voice/bench.py`, модели те же, что в сервере
голоса (`voice/server.py`): распознавание GigaAM v3 e2e RNNT через
onnx_asr, синтез TeraTTSv2 (дистиллированный сэмплер, 8 шагов).
Видеокарта не используется, только onnxruntime на процессоре.

**Машина:** AMD EPYC 7532, число потоков onnxruntime ограничено (4 и 6),
память восьмиканальная. **Во время замера машина была нагружена
другими задачами** (load average около 23 на 64 логических ядрах:
параллельно шли сборки и тесты). Цифры поэтому скорее пессимистичные
для этой машины — но это не машина из ТЗ: на настольном i7 с
двухканальной памятью мы не мерили и цифру не называем.

Каждая фраза — 5 прогонов; первый прогон (прогрев) отдельно, медиана —
по остальным четырём. RTF — время обработки, делённое на длительность
звука: меньше единицы — быстрее реального времени.

## Через API тренажёра

`POST /api/voice/tts` (голос `chief`, 7,6 с звука) — 1,03 с;
`POST /api/voice/asr` на том же звуке — 0,54 с. Сюда входят HTTP,
проверка токена и передача WAV.

## Вывод

На процессоре голос не упирается во время: синтез реплики идёт в
6–8 раз быстрее её звучания, распознавание — в 15–20 раз. Задержка
ответа собеседника складывается из распознавания (десятые доли
секунды), запроса звонка и синтеза (меньше секунды на фразу доклада),
то есть около полутора секунд до начала звука — при условии, что ответ
собеседника берётся из движка тренажёра, а не генерируется языковой
моделью. Языковая модель на процессоре добавила бы секунды (см.
`backend/docs/MODEL-SERVER.md`).
