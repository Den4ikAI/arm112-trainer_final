# UX-проход 1: преподаватель и оператор 112

29.09.2026, живой проход кликами в Playwright (headless) — как человек,
без прямых запросов к API (кроме подъёма стенда и заливки учебного
набора). Каждый шаг снят, ошибки консоли, исключения страницы и ответы
API с кодом ≥400 собирались по ходу.

- Кто: `teacher1` (1600×900) и параллельно `op01` (1920×1080, голосом
  через подставной микрофон), `op02` (1280×720), `op03` (1600×900).
- Стенд свой: сервер 127.0.0.1:8201, клиент 5301, база `arm112_ux1`,
  модель — Gemma на 8095, голос — 8092; учебный набор `deploy/seed`.
  Поднимается `frontend/e2e/ux/поднять.sh`, проход —
  `node frontend/e2e/ux/проход-1.mjs [клиент] [каталог кадров]`
  (в `npm test` не входит).
- Кадры: `docs/ux/1/` (номер шага · кто · ширина окна · шаг), сводка
  шагов и находок — `docs/ux/1/итог.json`.

Итог прохода до исправлений: 71 шаг, 5 упали; ошибок консоли,
исключений страницы и ответов ≥400 — **ни одного**.

### 1. «Начать» в «Экзаменах» начинало задание блица — исправлено

Шаги: преподаватель запускает для «Операторы 112 — группа 1» экзамен
«Экзамен 112: пожары, газ, человек в опасности», затем блиц
«Тренировка по частям: адрес» (оба из учебного набора, в обоих есть
один и тот же вызов). Курсант: «Экзамены» → «Начать» → «сохранить».

Было: вместо экзамена — «Разбор блица», «оценивается только „Адрес“»
(`docs/ux/1/061-op01-1920-экзамен.png`, `063-…-экзамен-разбор-скрыт.png`).
Экзамен оставался не начатым, в протоколе экзамена — пусто, и
преподавателю нечего было оценить экспертно (`069`, `070`).

Причина: клиент начинал вызов по одному `scenarioId`, а сервер без
номера задания брал занятие, запущенное последним. Сервер номер
задания (`assignmentId`) принимал и раньше — клиент его не передавал.
Теперь передаёт. Проверка: `марафон.spec.ts` «„Начать“ в экзамене идёт
в зачёт экзамена, а не блица с тем же вызовом» — без исправления
падает, с ним проходит.

### 2. Аналитика по ученикам открывалась пустой — исправлено

Шаги: «аналитика» → «Операторы 112 и диспетчеры ДДС · по ученикам».

Было: первая группа в списке — «Диспетчеры ДДС — группа 1», вкладка
всегда «Операторы 112»: «Обучающихся 0», пустые таблицы, а щёлкнуть
по ученику не по чему (`docs/ux/1/059-преп-1600-аналитика-ученик.png`).

Теперь, пока преподаватель сам не нажал вкладку, при пустой «112»
страница переходит на «Диспетчеры ДДС»; нажатая вкладка остаётся
нажатой. Вкладкам добавлен `aria-pressed`. Проверка:
`преподаватель.spec.ts` «аналитика группы диспетчеров открывается на
их вкладке…».

### 3. Одинокая запятая под номером вызова — исправлено

У вызовов, собранных вручную, нет имени и телефона заявителя, у части
подготовленных моделью — телефона. Под «Вызов № 5b7589» стояло «,»,
у модели — «Пожилая женщина,» (`docs/ux/1/024-…`, `044-…`). Теперь
выводится только то, что есть. Проверка: `разделы.spec.ts` «у вызова
без имени и телефона заявителя под номером нет одинокой запятой».

### 4. Учебный набор не перезаливался — исправлено

`deploy/seed/залить.py` удалял учебные учётные записи, а
`settings.updated_by` и `classifier_versions.imported_by` на них
ссылаются: как только преподаватель сохранил веса или параметры,
повторная заливка падала на внешнем ключе. Ссылки теперь обнуляются
перед удалением.

### 5. Блиц: пустой сегмент — 33 балла — описано

Шаги: «Тренировка по частям» → «Начать» → сразу «сохранить», адрес
пустой.

Видно: «33 балла», «Заполнено верно (0)», три «НЕ ЗАПОЛНЕНО»
(`docs/ux/1/063-op01-1920-экзамен-разбор-скрыт.png`).

Причина: `backend/src/domain/drill.rs`, `score_of` — максимум считается
только по замечаниям (`замечаний × 3`), верно заполненные поля в
знаменатель не входят. Пустой адрес из трёх полей: штраф 6 из 9 → 33.
Верно заполненные три поля и одно пропущенное: штраф 2 из 3 → тоже 33.
Курсант, заполнивший почти всё, и не заполнивший ничего получают один
балл. Для исправления нужен счёт проверок сегмента по эталону (сколько
полей сегмента в `expected`), а в `restrict` есть только замечания —
это правка оценки на сервере, в 20 минут не укладывается.

### 6. Нет общей навигации преподавателя — описано

Ссылки «занятия · вызовы · аналитика · веса оценки» есть только на
«Занятиях». На «Учебном материале», «Ходе занятия по местам», «Весах
оценки» и «Аналитике» — только «← В журнал»: из материала в занятия,
из весов в аналитику преподаватель идёт через журнал (`002`, `012`,
`057`, `058`). Проход фиксировал это находкой «нет ссылки» четыре раза.

### 7. 1280×720: панель курсанта закрывает карточку — описано

На 1280×720 панель обучающегося стоит внизу и занимает ~280 px из
720: от карточки видно ~300 px, опросная карта после выбора типа уходит
под панель, службы видны только в подвале
(`docs/ux/1/024-op02-1280-вопрос-из-списка.png`, `036-…-F5-…`). Панель
сворачивается «▾», но по умолчанию развёрнута. На 1600×900 и 1920×1080
панель справа, всё помещается (`044-op01-1920-…`).

### 8. Ручной вызов: адрес эталона никто не называет — описано

Преподаватель собрал вызов вручную: первая фраза «Алло! У соседей из
окна дым и пламя!», один вопрос «Пострадавшие есть?», адрес эталона —
Бутлерова, 8. Конструктор сохранил и дал утвердить. Курсант адрес
узнать не может ни из фразы, ни из ответов, а в разборе получает две
«ОШИБКИ» адреса (`docs/ux/1/052-op01-1920-повторно-только-просмотр.png`).
У вызовов учебного набора для этого есть вопрос «Уточните точный адрес».
Предложение: в конструкторе предупреждать, если значения эталона
(улица, дом) не встречаются ни в первой фразе, ни в ответах.

### 9. «Опер. , АРМ 4» в шапке карточки — описано

`CardHeader.tsx`: строка «Опер. , АРМ {n}, {ФИО}» — перед запятой
пусто. Похоже на перенос с кадров исходного АРМ; не трогал.

### 10. Правка перепиской: 500 «internal» при сбое модели — описано

Всплыло на повторном проходе (после исправлений), на том же замечании
«Сделай заявителя пожилой женщиной и добавь, что в подвале слышен
треск», которое в первом проходе прошло. Через ~14 с сервер ответил
`500 {"error":"internal"}`, в журнале сервера — «в ответе модели нет
JSON: {"patch": {"applicantName": "Пожилая женщина", "hidden": […]…»
(`docs/ux/1/после/итог.json`). Ответ модели разобрать не удалось —
судя по началу, JSON оборван или испорчен.

`api/scenarios.rs`, обработчик переписки: сбой применения правки уже
превращён в понятную реплику, а сбой самой модели
(`scenario_edit::turn(...).map_err(AppError::Other)`) — по-прежнему
500 «internal». Предложение: отдавать 503 с текстом «Модель ответила
не по форме — повторите замечание», как для недоступной модели.
Замечание преподавателя при этом уже записано в переписку.

### 11. Утвердить можно, пока модель правит вызов — описано

В той же переписке, пока в чате «модель думает…», кнопка «утвердить»
активна; проход её нажал — вызов утверждён до того, как правка пришла
(`docs/ux/1/после/004-…`, `005-…`). Если бы правка пришла успешно, она
легла бы на уже утверждённый вызов. Предложение: блокировать
«утвердить» на время хода модели.

### 12. В «Экзаменах» тема вызова — код типа — описано

В строках экзамена тема — «1. 101», «2. 101»… (`docs/ux/1/после/061-…`):
курсант до начала вызова видит код типа происшествия, который ему и
предстоит определить. Для обычных занятий это, возможно, удобно; для
экзамена — подсказка. Решение за командой.

## После исправлений

Повторный проход тем же скриптом на том же стенде: курсант начинает
экзамен из «Экзаменов», разбор скрыт до конца, в строке «закончено» и
«…» вместо балла (`docs/ux/1/после/061-…`); преподаватель открывает
попытку из протокола экзамена и ставит экспертную оценку 85 с
комментарием (`070-…`); аналитика по ученикам открывается на
диспетчерах ДДС и щелчок по ученику ведёт в его карточку (`059-…`).
Три упавших шага повторного прохода — ожидаемые: экзамен и блиц уже
шли с первого прохода, веса уже были сохранены с тем же значением.

## Что работает (проверено тем же проходом)

- Вызов по описанию (модель) — черновик; правка перепиской
  («сделай заявителя пожилой женщиной…») меняет ФИО и ответы, модель
  пишет, что изменила (`004`).
- Ручная сборка вызова и происшествия ДДС, эталон и службы от
  классификатора, утверждение (`006`–`009`).
- Составление занятия по названиям вызовов, запуск, «Ход занятия по
  местам» — счётчики и последний балл обновляются по ходу работы
  курсантов (`010`–`012`, `053`).
- Курсант: разделы, вопрос из списка, вопрос своими словами
  («Скажите, пострадавшие есть?» → верный ответ), вопрос голосом
  (распознан и отвечен), адрес, два типа, опросная карта, описание;
  F5 посреди вызова — адрес и типы на месте; «сохранить» → разбор;
  повторное открытие — только просмотр (`022`–`052`).
- Веса: ползунок сразу пересчитывает «стало», «Сохранить и
  пересчитать» пересчитывает 3 из 3 попыток (`056`, `057`).
- Ошибок консоли, исключений и ответов API ≥400 за проход нет.

Вопрос голосом шёл с подставного микрофона Chromium: файл с фразой
«Скажите, дом газифицирован?» (синтез голосового сервиса) проигрывается
по кругу, поэтому в стенограмме фраза дважды — это особенность
подстановки, не продукта.
