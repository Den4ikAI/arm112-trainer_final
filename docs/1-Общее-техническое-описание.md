## 1. Назначение

Тренажёр — учебное программное обеспечение для подготовки специалистов
дежурно-диспетчерских служб (ДДС) города Москвы. Обучаемый работает
на рабочем месте, повторяющем рабочее место диспетчера в системе
ПОВ-112 (АРМ-112): те же карточки происшествий, статусы реагирования,
список служб. Поверх рабочего места лежит учебный слой: задания,
нормативы времени, учебная бригада и её доклады, IP-телефон, разбор
с оценкой и рекомендациями.

Основная схема обучения, на которую рассчитан продукт:

```
преподаватель ──► задание ──► обучаемый (диспетчер ДДС) ──► результат ──► рекомендации
      ИИ     ──►  задание ──►        тот же обучаемый      ──► результат ──► следующее задание
```

Задание обучаемому выдаёт либо преподаватель (занятие, экзамен,
тренировка по частям), либо искусственный интеллект — по одному нажатию
обучаемого, без участия преподавателя. Результат каждого задания
обучаемый видит сразу в разборе; преподаватель видит ход занятия,
протокол, аналитику и ставит экспертную оценку.

Второе рабочее место — оператор 112 (приём вызова и заполнение карточки
112) — в продукте есть, но по умолчанию свёрнуто: его включает
администратор. Данные и код оператора 112 при этом остаются на месте.

Продукт работает в закрытом контуре: все компоненты, включая языковую
модель и голос, работают на одной машине без выхода в интернет.

## 2. Функции и возможности

### 2.1. Рабочее место диспетчера ДДС

| Функция | Что делает |
|---|---|
| Лента происшествий службы | Диспетчеру приходят только происшествия его службы; несколько карточек могут идти одновременно, время считается у каждой |
| Карточка происшествия | Поля карточки 112 только для чтения; диспетчер ведёт статусы, комментарии, бригаду |
| Статусы реагирования | «Принята» / «Не принята», затем «Начало реагирования» → «Прибытие» → «Проведение работ» → «Работы завершены» или «Отказ от выполнения работ»; порядок и обязательные комментарии проверяет сервер |
| Нормативы | Открыть карточку за 30 с, первая запись (статус и текст) за 3 мин; таймер на экране, просрочка — в разборе |
| Учебная бригада | Назначение бригады из списка службы; этапы работ наступают по шкале времени; старший докладывает с задержкой |
| IP-телефон | Программная эмуляция IP-телефона, открывается зелёным кружком с трубкой на карточке: внутренний номер, телефонная книга из справочника службы (до 10 абонентов: руководитель организации, начальник отдела реагирования, начальник и специалист аварийной бригады, заявитель — если включил преподаватель), набор номера, входящие с АОН, удержание, журнал вызовов, запись разговора в WAV |
| Доклад начальнику | Звонок вышестоящему начальнику; начальник переспрашивает пропущенное и говорит «Принял»; разбор доклада по каждому сведению |
| Разговор голосом | Речь в микрофон распознаётся, ответы собеседников синтезируются; без сервера голоса — всё текстом |
| Разбор | После «Работы завершены»: замечания с ценой ошибки, «статусы по факту», нормативы, анализ комментариев нейросетью, прогноз и рекомендации |
| Происшествие от ИИ | Кнопка «Новое происшествие от ИИ» — система собирает происшествие для службы диспетчера и кладёт в ленту; преподаватель не нужен |
| Следующее задание от ИИ | После разбора — рекомендация «что тренировать дальше» и кнопка «Следующее задание от ИИ»: новое происшествие своей службы, помеченное рекомендацией, которую оно отрабатывает; следующий разбор отмечает, сработала ли рекомендация |
| Подсказки | Кнопка «Подсказки» (в ленте — «?»): тур по окнам рабочего места в порядке памятки ДДС — что это окно и когда им пользоваться |

### 2.2. Рабочее место оператора 112 (включается администратором)

Карточка 112 по кадрам АРМ-112, несколько типов происшествия в одной
карточке, опросные карты для 44 из 51 типа «Что случилось?», подбор
служб классификатором (1 283 позиции ЕКП, 211 служб), разговор с
заявителем вопросами из списка, своими словами или голосом, разбор
«выяснил или угадал».

### 2.3. Преподаватель

| Функция | Что делает |
|---|---|
| Учебный материал | Происшествия ДДС и вызовы 112: от ИИ по одной службе, по описанию (черновик модели), вручную; правка и утверждение; эталон служб всегда считает классификатор |
| Занятия | Обычное занятие, экзамен («Марафон»), тренировка по частям («Блиц»); выбор группы, материала, интервала карточек |
| Ход занятия по местам | Страница идущего занятия: таймеры против норматива, ход заполнения, кто опаздывает; режим проектора |
| Телефонный справочник ДДС | Преподаватель формирует справочник номеров службы, в том числе — звонить ли заявителю |
| Журнал вызовов и записи | Журнал IP-телефона по каждой карточке; запись разговора слушает преподаватель |
| Разбор и экспертная оценка | Все попытки по карточке, балл 0–100 с комментарием рядом с автоматическим; вердикт по каждому замечанию нейросети |
| Веса оценки | Семь групп проверок с ползунками и пересчётом «было → стало» по всем попыткам |
| Аналитика | По группе и по ученику: балл, время против норматива, тепловая карта ошибок, прогноз против факта, сводка |
| Группы и рабочие места | Состав групп, назначение рабочего места курсанту (ДДС своей службы или 112) |

### 2.4. Администратор

Учётные записи и роли, версии классификатора, параметры (нормативы,
шкала бригады, телефония, включение системы 112, движки ИИ), журнал
действий, состояние системы. Подробно — «Руководство администратора».

### 2.5. Искусственный интеллект

| Задача | Чем решается | Что гарантирует код |
|---|---|---|
| Формирование задания для ДДС | Классификатор выбирает позицию, по которой служба реагирует; модель пишет текст карточки (заявитель, описание) под уже проверенные признаки | Службы считает классификатор, не модель; адрес из учебного набора; без модели карточка собирается из ответов карты |
| Черновик вызова по описанию преподавателя | Языковая модель по строгой JSON-схеме | Признаки — только из словаря опросной карты; эталон пересчитывается классификатором |
| Оценка действий | Правила над тремя слоями данных: скрытая истина, стенограмма, карточка | Разбор ДДС: статусы по докладам, бригада, нормативы, комментарии |
| Анализ свободного текста | Языковая модель или кросс-энкодер OpenJEV | Каждое замечание с цитатой, которую проверяет код; балл модель не меняет |
| Рекомендации | Поиск повторяющихся ошибок в последних разборах | Текст из замечаний разбора; в следующем разборе ставится вердикт «ушла / нет» |
| Прогноз результата | Гребневая регрессия на истории курсанта | Фиксируется до начала задания, сверяется с фактом |
| Голос | GigaAM v3 (распознавание), TeraTTSv2 (синтез) | Что говорит собеседник — решает движок тренажёра, голос только произносит |

## 3. Состав и архитектура

![Архитектура](картинки/архитектура.png)

*Рис. 1. Компоненты тренажёра. Всё работает на одной машине без выхода
в интернет; нейросетевые сервисы необязательны.*

| Компонент | Технология | Назначение |
|---|---|---|
| Веб-клиент | React 19, TypeScript, Vite | рабочие места, учебный слой, IP-телефон |
| Сервер приложения | Rust, axum, tokio | API, домен, оценка, фоновые задачи, канал событий WebSocket |
| Хранилище | PostgreSQL 16 | классификатор, карточки, занятия, вызовы телефона и записи, журналы, параметры |
| Языковая модель | GigaChat 3.1 10B-A1.8B на llama.cpp (процессор) или Gemma 4 / Qwen3.8 на vLLM (видеокарта) | подготовка заданий, правка по переписке, анализ текста, сводки |
| Голос | GigaAM v3 и TeraTTSv2, ONNX на процессоре | разговор голосом: старший бригады, начальник, заявитель |
| Сверка описания | кросс-энкодер OpenJEV (Qwen3.5 2B/4B), PyTorch на процессоре | сверка описания курсанта с фактами |
| Веб-сервер | nginx | статика клиента, HTTPS, прокси `/api` и `/ws` |

Сервер приложения разделён на слои: `api/` (HTTP, OpenAPI), `domain/`
(классификатор, статусы, оценка, бригада, прогноз, рекомендации,
формирование происшествий — чистые функции без HTTP и моделей),
`ingest/` (импорт классификатора и билетов), `jobs/` (сторож
нормативов, доклады бригад, очередь модели), `ml/` (адаптеры моделей
и заглушка). Все 437 серверных проверок выполняются без модели.

Клиент — слоистая раскладка `shared → entities → widgets → pages`,
HashRouter, поэтому собранный клиент отдаётся статикой. Канал событий
WebSocket ускоряет интерфейс, но не является источником истины: при его
отказе всё работает на обычных запросах.

Разграничение ролей проверяется на сервере при каждом запросе; интерфейс
скрывает недоступные разделы, но не является средством защиты.

Описание API — `https://<стенд>/api/docs` (OpenAPI).

## 4. Требования к оборудованию

| | Минимум | Почему |
|---|---|---|
| Процессор | 6 ядер x86-64 | замер модели 14,8 токенов/с сделан на шести потоках |
| Память | 16 ГБ без модели, **32 ГБ с моделью**; с кросс-энкодером 2B — ещё 9 ГБ | веса модели 6,45 ГБ плюс контекст |
| Диск | 40 ГБ | образы, сборка, веса, база и копии |
| ОС | Ubuntu 22.04 или 24.04 | проверено на них |
| Видеокарта | не нужна | всё на процессоре; при наличии RTX 4090 — профиль GPU |
| Сеть | один открытый порт HTTPS (443) и 80 для переадресации | рабочие места подключаются браузером |

Рабочее место обучаемого и преподавателя — любой компьютер с современным
браузером (Chrome, Edge, Firefox), микрофоном и наушниками или
гарнитурой. Интерфейс работает и на телефоне.

Проверенная нагрузка: 100 одновременных пользователей — максимум
отклика 0,69 с, ошибок 0; 50 заданий, начатых в одну секунду, — все
дошли до разбора. Методика — `backend/docs/замеры/НАГРУЗКА.md`.

## 5. Порядок монтажа

### 5.1. Стенд одной командой

На чистой виртуальной машине с Docker (compose 2.20 и новее):

```bash
git clone <репозиторий> && cd <каталог>
deploy/up.sh
```

Скрипт при первом запуске:

1. создаёт `deploy/.env` со случайным паролем базы и ключом подписи
   токенов;
2. выпускает самоподписанный сертификат HTTPS на адрес машины
   (`deploy/tls/`); свой сертификат — положить туда `cert.pem` и
   `key.pem` до запуска;
3. включает модель, голос и кросс-энкодер, только если находит их веса
   (`/opt/arm112/model`, `/opt/arm112/voice`, `/opt/arm112/nli`) или
   адрес уже развёрнутого сервера (`ML_BASE_URL`, `VOICE_BASE_URL`,
   `NLI_BASE_URL`);
4. собирает образы и ждёт, пока сервер ответит; в конце печатает адрес.

При первом старте сервер накатывает миграции (в них учебные учётные
записи и параметры) и импортирует классификатор из `task/*.xlsx`.

| Сервис | Что это | Наружу |
|---|---|---|
| `web` | nginx: клиент, HTTPS, прокси | `WEB_TLS_PORT` (443), `WEB_PORT` (80 → 443) |
| `backend` | сервер тренажёра; ежесуточная копия базы | нет |
| `db` | PostgreSQL 16 | нет |
| `model` | llama.cpp с патчем MTP и весами GigaChat | нет |
| `voice` | распознавание и синтез речи | нет |
| `nli` | кросс-энкодер OpenJEV | нет |

Первая сборка на 6 ядрах: сервер 10–15 мин, сервер модели 5–10 мин,
клиент 1–2 мин. Повторный `up.sh` пересобирает только изменившееся,
данные базы в томе не трогает.

Открыть входящие TCP 443 и 80 в группе безопасности облака или `ufw`.

### 5.2. Проверка стенда

```bash
deploy/check.sh                                 # на самой машине
deploy/check.sh https://<адрес>                 # с рабочего места
docker compose -f deploy/docker-compose.yml ps  # все сервисы healthy
```

`check.sh` ничего не меняет: входит учебной учётной записью и проверяет
клиент, сервер, журнал, классификатор, канал событий, описание API и
подключение модели.

### 5.3. Учебный набор

Чистый стенд наполняется учебным набором: 20 происшествий ДДС и 20
вызовов 112 по 10 темам, 2 группы диспетчеров и 2 группы операторов по
5 человек, по 2 экзамена и 2 тренировки по частям на роль. Скрипт
**очищает учебные данные**, поэтому сначала — копия базы:

```bash
cd deploy
docker compose exec -T db pg_dump -U arm112 -Fc arm112 > ../arm112-до-набора.dump
ARM112_DB_CONTAINER=arm112-db-1 python3 seed/залить.py https://127.0.0.1 arm112
```

### 5.4. Языковая модель

Файл весов `full-mtp-q4_K_M.gguf` (6,45 ГБ, своя конвертация с блоком
MTP) копируется в `/opt/arm112/model/`:

```bash
sudo mkdir -p /opt/arm112/model && sudo chown "$USER" /opt/arm112/model
rsync -avP /путь/к/full-mtp-q4_K_M.gguf <пользователь>@<ВМ>:/opt/arm112/model/
```

Каталог и имя файла — `MODEL_DIR`, `MODEL_FILE` в `deploy/.env`.
Модель на другой машине контура: `ML_BASE_URL=http://адрес:порт`
(любой сервер, совместимый с OpenAI API: llama.cpp, vLLM, Ollama).
Вне Docker: `backend/docs/MODEL-SERVER.md`.

Профиль с видеокартой: Gemma 4 26B-A4B (INT4) или Qwen3.8-27B (INT4)
в vLLM на одной RTX 4090 — `deploy/gpu/start-vllm.sh`; в `deploy/.env`
указать `ML_BASE_URL`. На видеокарте имеет смысл включить параметры
`chief.live_model = 1` и `applicant.live_model = 1`.

### 5.5. Голос

Веса `istupakov/gigaam-v3-onnx` и `TeraSpace/TeraTTSv2` (около 2 ГБ)
в `/opt/arm112/voice/` — команда загрузки в `deploy/README.md`, шаг 3а.
Машина без интернета — скачать там, где он есть, и скопировать
`rsync`-ом. Каталог — `VOICE_DIR`, потоки — `VOICE_THREADS` (4).

### 5.6. Кросс-энкодер сверки описаний

Чекпоинт `AlexWortega/openjev` (`qwen3.5-2b-nli-v5`, 4,2 ГБ на диске,
около 9 ГБ памяти) в `/opt/arm112/nli/`. Без него описание сверяет
языковая модель — медленнее и хуже видит упущенное.

### 5.7. Локальный запуск без Docker

| Компонент | Версия |
|---|---|
| Rust | 1.98 и новее |
| Node.js | 20.19 и новее |
| PostgreSQL | 14 и новее |

```bash
docker run -d --name arm112-db -e POSTGRES_USER=arm112 \
  -e POSTGRES_PASSWORD=arm112 -e POSTGRES_DB=arm112 -p 5432:5432 postgres:16
cd backend && cp .env.example .env && cargo run --release        # :8080
cargo run --release --bin import_classifier -- \
  ../task/Классификатор_происшествий_v_046_24*.xlsx "v046_24"      # один раз, затем перезапуск
cd frontend && npm run install:all && npm run build                # или npm run dev (:5173)
```

### 5.8. Подключение рабочих мест

Рабочие места открывают `https://<адрес стенда>/` в браузере.
Самоподписанный сертификат браузер один раз попросит подтвердить.
Микрофон браузер даёт только защищённой странице (HTTPS); по `http://`
кнопка микрофона неактивна и объясняет почему.

## 6. Настройка функционирования

### 6.1. Переменные окружения стенда (`deploy/.env`)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `WEB_TLS_PORT`, `WEB_PORT` | порт HTTPS и порт переадресации | 443, 80 |
| `DB_USER`, `DB_NAME`, `DB_PASSWORD` | база; пароль не менять после первого запуска | `arm112`, случайный |
| `DEMO_PASSWORD` | демонстрационный стенд: пароль учебных записей; задан — экран входа показывает записи списком, вход одним щелчком. В рабочей установке оставить пустым | пусто |
| `JWT_SECRET`, `JWT_TTL_HOURS` | подпись и срок токенов входа | случайный, 8 ч |
| `MODEL_DIR`, `MODEL_FILE`, `MODEL_THREADS`, `MODEL_CTX` | языковая модель | `/opt/arm112/model`, `full-mtp-q4_K_M.gguf`, 6, 8192 |
| `ML_BASE_URL` | модель на другой машине контура | не задан |
| `VOICE_DIR`, `VOICE_THREADS`, `VOICE_STYLES`, `VOICE_PHONE_ROLES`, `VOICE_BASE_URL` | голос: веса, потоки, голоса ролей, кого слышно «через телефон», внешний сервер | `/opt/arm112/voice`, 4 |
| `NLI_DIR`, `NLI_MODEL`, `NLI_THREADS`, `NLI_BASE_URL` | кросс-энкодер | `/opt/arm112/nli`, `qwen3.5-2b-nli-v5`, 6 |
| `BACKUP_KEEP_DAYS` | сколько дней хранить ежесуточные копии базы | 14 |
| `TLS_HOST` | имя машины для самоподписанного сертификата | не задано |
| `RUST_LOG` | уровень журнала сервера | `info` |

Сервер вне Docker читает `backend/.env`: `DATABASE_URL`,
`TEST_DATABASE_URL`, `BIND_ADDR`, `JWT_SECRET`, `ML_PROVIDER`
(`http` или `mock`), `ML_BASE_URL`, `VOICE_BASE_URL`, `NLI_BASE_URL`,
`DEMO_PASSWORD`, `BACKUP_DIR`, `BACKUP_KEEP_DAYS`.

### 6.3. Экран входа

С заданным `DEMO_PASSWORD` экран входа показывает учебные учётные записи
списком — по одной на роль и службу — и вход выполняется одним щелчком.
Там же переключатель «Система 112»: включить или выключить рабочее
место оператора 112 можно, введя логин и пароль администратора. Без
`DEMO_PASSWORD` — обычная форма логина и пароля.

### 6.4. Сертификат HTTPS

Самоподписанный сертификат выпускается на адрес машины при первом
запуске. Если стенд открывают по другому адресу или имени — задать
`TLS_HOST` и удалить `deploy/tls/`, затем повторить `up.sh`; либо
положить свой сертификат.

## 7. Возможные неисправности

| Признак | Причина | Что делать |
|---|---|---|
| `up.sh` пишет «файла модели нет — поднимаю без неё» | Весов в `MODEL_DIR` нет | Это штатный режим: классификация, занятия, оценка, прогноз, рекомендации работают; нет черновиков по описанию, сводки по группе и анализа текста (блок помечается «модель недоступна»); происшествие от ИИ собирается без текста модели — описание из ответов карты. Скопировать веса и повторить `up.sh` |
| «Голос не подключён — собеседник отвечает текстом», кнопки «Сказать голосом» нет | Сервер голоса не поднят или недоступен (`VOICE_DIR`, `VOICE_BASE_URL`) | Разговор идёт текстом. Проверить веса в `VOICE_DIR`, `docker compose logs voice` |
| Кнопка микрофона неактивна, подсказка «Микрофон браузер даёт только по HTTPS» | Стенд открыт по `http://` | Открыть `https://<адрес>/`, подтвердить сертификат |
| «Нет доступа к микрофону — говорите текстом» | Браузер не дал доступ к микрофону | Разрешить микрофон для сайта в настройках браузера; говорить можно текстом |
| «Не расслышано — повторите», «Распознать не вышло — скажите текстом» | Тихая или короткая фраза, сбой распознавания | Повторить ближе к микрофону или ввести текстом |
| Нет опросных карт, службы не подбираются | Классификатор не загружен | `docker compose logs backend`: при первом старте он импортируется из `task/*.xlsx`; вручную — `import_classifier`, затем активировать версию в администрировании |
| «Сервер не отвечает», «Нет связи с сервером» | Сервер или база не поднялись | `docker compose ps`, `docker compose logs backend db`; `deploy/check.sh` |
| Сервер в базу не входит после смены `DB_PASSWORD` | Пароль задаётся один раз при создании тома | Вернуть прежний пароль в `deploy/.env` |
| Браузер предупреждает о сертификате | Самоподписанный сертификат | Подтвердить один раз; или положить свой в `deploy/tls/` |
| Экран входа без списка учётных записей | `DEMO_PASSWORD` не задан | Задать в `deploy/.env` (только на демонстрационном стенде), повторить `up.sh` |
| Нет рабочего места оператора 112 | Параметр `ui.op112 = 0` | Включить в «Параметрах» или переключателем «Система 112» на экране входа паролем администратора |
| Телефон не открывается, звонки кнопками в карточке | `ui.phone = 0` | Включить в «Параметрах» |
| Нет записи разговора в журнале телефона | `phone.record = 0` или голос не подключён | Включить запись; без голоса сохраняется только текст реплик |
| Входящий от старшего бригады стал «пропущенным» | Не ответили за `phone.ring_sec` | Доклад старшего всё равно есть в списке бригады; увеличить `phone.ring_sec` |
| «ИИ готовит происшествие…» долго | На процессоре модель пишет текст до двух минут | Подождать; повторное нажатие не ставит второе в очередь |
| Прогноз равен среднему баллу курсанта | Пар «прогноз — факт» меньше 30 | Штатно: до накопления истории работает базовая линия |
| Сводка по группе считается долго | Модель на процессоре, около минуты | Подождать или перейти на профиль с видеокартой |
| Карточка перешла в «Не оповещено» / «Не завершено» | Сторож нормативов: не открыта в срок / не завершена за `norm.completion_hours` | Штатно; сроки в «Параметрах» |
| Значение параметра не сохраняется, «Нужно число» или 400 | Вне допустимых пределов | См. пределы в таблице 6.2 |
| Канал событий оборвался | Сбой сети | Переподключается сам с возрастающей задержкой; данные не теряются, правки повторяются после возврата сети (проверено на обрыве до 30 с) |

Журналы: `docker compose -f deploy/docker-compose.yml logs backend`
(уровень — `RUST_LOG`), состояние — вкладка «Состояние» у администратора
и `GET /api/admin/health`.

Резервные копии базы делаются ежесуточно в том `backups`
(`BACKUP_KEEP_DAYS` дней). Восстановление:
`docker compose exec -T db pg_restore -U arm112 -d arm112 -c < копия.dump`.
