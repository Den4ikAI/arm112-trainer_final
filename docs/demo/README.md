# Демо-ролик

Сценарий сам проходит тренажёр от подготовки вызова до разбора и
записывает экран с титрами и закадровым голосом. Воспроизводимо: тот
же сценарий на новой версии даёт новый ролик одной командой.

```bash
docs/demo/build.sh gpu    # профиль с видеокартой: Gemma 4 26B-A4B в vLLM (:8095)
docs/demo/build.sh cpu    # без видеокарты: GigaChat 3.1 на процессоре
```

Ролик — `../lct_hack-demo/демо-<профиль>.mp4` (вне репозитория,
`DEMO_VIDEO_DIR` меняет каталог): 1920×1080, 30 кадров/с, H.264 + AAC.

## Что показано

1. **Преподаватель** открывает готовый вызов из билета, правит его
   замечанием в диалоге с моделью и утверждает (подготовка новых вызовов
   моделью в ролик не входит — она идёт минутами в фоновой очереди).
2. **Оператор 112** открывает вызов, выданный преподавателем занятием
   (раздел «Учебные вызовы»), задаёт вопросы заявителю, заполняет
   адрес, тип и опросную карту; службы подтягиваются по классификатору;
   описание нарочно с ошибкой («есть пострадавший»). Разбор: балл,
   «угадал» для не выясненного вопросом, анализ описания нейросетью
   с цитатами.
3. **Диспетчер ДДС** видит в ленте происшествие, которое преподаватель
   выдал группе диспетчеров занятием ДДС (карточки курсантов 112 к
   диспетчерам сами не попадают), открывает («получена
   службой»), принимает, направляет бригаду, получает доклад старшего,
   звонит старшему **голосом** (реплика синтезируется и подаётся вместо
   микрофона, распознаёт её настоящий сервер голоса), докладывает
   вышестоящему начальнику; модель разбирает доклад.
4. **Преподаватель** ставит экспертную оценку, смотрит аналитику и
   прогноз, показывает режимы занятий — марафон и блиц.

Этапы работ бригады в ролике ускорены (в базе сдвигается время этапа),
это сказано в титре. Выдача вызова курсанту и происшествия диспетчеру
делается в базе теми же записями, что создаёт занятие преподавателя
(как в `frontend/e2e/tests/helpers.ts`), в момент начала сцены. На процессоре ожидания модели сжимаются при
сборке в `DEMO_SPEEDUP` раз (по умолчанию 8) и помечены на экране
плашкой «ускорено ×8».

## Как устроено

| Файл | Что делает |
|---|---|
| `frontend/e2e/demo/kit.ts` | курсор, отметка клика, титры, плашки — вставляются в страницу; запись экрана через CDP screencast (JPEG с отметками времени — чётче встроенного видео Playwright); закадровый голос и реплики собеседников — в дорожку по отметкам времени; поддельный микрофон |
| `frontend/e2e/demo/steps.ts` | шаги сюжета — независимые куски, можно переставлять и добавлять |
| `frontend/e2e/demo/путь.demo.ts` | порядок шагов; `DEMO_PARTS=intro,operator` — снять часть |
| `frontend/e2e/playwright.demo.config.ts` | отдельный конфиг, в `npm test` не входит |
| `docs/demo/server.sh` | свой экземпляр тренажёра: API :8171, клиент :5271, база `arm112_demo` |
| `docs/demo/narrator.sh` | сервер голоса для диктора (:8193): голоса `narrator` и `operator` |
| `docs/demo/revoice.py` | переозвучка записи: диктор FireRed, заявительница `x_alina`, телефонный кодек |
| `docs/demo/assemble.py` | кадры + звук → MP4 (ffmpeg, numpy, soundfile) |
| `docs/demo/build.sh` | всё вместе: чистая база → экземпляр → запись → сборка |
| `docs/demo/frames.sh` | вынуть кадры ролика по секундам — проверить глазами |

Звуки самого приложения (ответы старшего и начальника) Playwright не
записывает, поэтому те же реплики синтезируются тем же голосом и
кладутся в дорожку в момент, когда они появились на экране.

Голоса при записи — стили из поставки TeraTTSv2: диктор `ru_f2`, оператор 112 `ru_m5`, диспетчер ДДС `ru_f1`, заявитель `ru_f1` или `ru_m1`,
старший бригады `ru_m5`, начальник `ru_m1` (PROVENANCE.md, «Голос»).

После записи звук переозвучивается `docs/demo/revoice.py` без новой
съёмки: диктор — FireRed TTS3 (HF Space) по образцу голоса Александра
Головченко (`ref-sasha.wav` вне репозитория, PROVENANCE.md), заявительница — клон стиля Алины `x_alina` в
TeraTTSv2 (стиль вне репозитория, PROVENANCE.md). Реплики «по телефону» —
заявитель, старший бригады, начальник — пропущены через телефонный
кодек (полоса 300–3400 Гц, 8 кГц, μ-law); диктор, курсант и микрофон
диспетчера — без кодека. Каждая фраза сверяется с исходной по длительности
и проверяется распознаванием на сервере голоса.

Заготовка под свободный голосовой вопрос заявителю 112 —
`voiceQuestion112` в `steps.ts`: шаг включается сам, когда в диалоге 112
появится кнопка `data-testid="ask-voice"`.

## Что нужно на машине

- контейнер базы `arm112-db`, собранный backend (`cargo build`),
  `node_modules` в `frontend/apps/react` и `frontend/e2e`;
- сервер модели: vLLM с Gemma 4 26B-A4B на :8095 (`deploy/gpu/start-vllm.sh`) или
  llama.cpp с GigaChat на :8090;
- сервер голоса на :8092 для приложения и веса голоса для диктора
  (`VOICE_MODELS_DIR`, по умолчанию `/media/denis/work4/llm/voice`);
- ffmpeg, Python с numpy и soundfile (`DEMO_PY`, по умолчанию venv
  сервера голоса).

Переозвучка после записи: `docs/demo/revoice.py narrator <каталог>`
(системный python, нужен `firered.py` из
`FIRERED_DIR`), затем `$DEMO_PY docs/demo/revoice.py phone <каталог>`
(venv сервера голоса) и `assemble.py`. Звуки берутся из `sounds.json`,
диктор — тем же текстом, что уходил при записи (`spoken()` из `kit.ts`).

Если запись оборвалась, кадры и звук остаются в
`/tmp/arm112-demo/<профиль>/`, а `assemble.py` соберёт из них то, что
успело записаться.

## Ролики финала: преподаватель и два обучаемых

Запись трёх рабочих мест одновременно — «сеть: ПК преподавателя и два
ПК обучаемых». Каждое место — свой контекст браузера на одном
экземпляре тренажёра, свой CDP screencast; в кадре 1920×1080 активное
место крупно (1280×720 без масштабирования), остальные два — живые
миниатюры справа, титр диктора снизу.

| Файл | Что делает |
|---|---|
| `frontend/e2e/demo/студия.ts` | `Studio` (диктор, заставки, пометки, «какой экран главный») и `Screen` (контекст, курсор, запись кадров) |
| `frontend/e2e/demo/финал.demo.ts` | главный ролик: занятие, задания от ИИ у dds01 (101) и dds02 (104), бригада и IP-телефон, статусы по докладам, разбор, рекомендация, следующее задание от ИИ, аналитика |
| `frontend/e2e/demo/финал-короткие.demo.ts` | «IP-телефон и справочник», «Администратор и система 112» |
| `docs/demo/assemble_multi.py` | кадры всех экранов + звук → MP4 (ffmpeg, numpy, Pillow — системный python3) |

Готовые ролики — `docs/video/финал-*.mp4`.

Пересъёмка:

```bash
# свой экземпляр на копии базы показа (постгрес в arm112-db), Gemma :8095, голос :8092
cd backend && DATABASE_URL=postgres://arm112:arm112@localhost:5432/arm112_demo_final \
  BIND_ADDR=127.0.0.1:8484 ML_PROVIDER=http ML_BASE_URL=http://127.0.0.1:8095 ML_MODEL=local \
  VOICE_BASE_URL=http://127.0.0.1:8092 DEMO_PASSWORD=arm112 cargo run
cd frontend/apps/react && VITE_API_TARGET=http://127.0.0.1:8484 npx vite --host 127.0.0.1 --port 5471 --strictPort

# шкала бригады и звонок — короче, чем в бою (в своей базе)
docker exec -i arm112-db psql -U arm112 -d arm112_demo_final -c "
  UPDATE settings SET value='8'  WHERE key='brigade.start_sec';
  UPDATE settings SET value='18' WHERE key='brigade.arrive_sec';
  UPDATE settings SET value='15' WHERE key='brigade.work_start_sec';
  UPDATE settings SET value='20' WHERE key='brigade.work_sec';
  UPDATE settings SET value='2'  WHERE key='brigade.report_delay_sec';
  UPDATE settings SET value='15' WHERE key='phone.ring_sec';"

cd frontend/e2e
DEMO_WEB_PORT=5471 DEMO_DB=arm112_demo_final DEMO_NARRATOR_URL=http://127.0.0.1:8092 \
  DEMO_OUT=/tmp/arm112-demo/final npx playwright test --config playwright.demo.config.ts финал.demo
python3 ../../docs/demo/assemble_multi.py /tmp/arm112-demo/final ../../docs/video/финал-преподаватель-и-обучаемые.mp4 28

# короткие — тем же способом, по одному тесту
DEMO_OUT=/tmp/arm112-demo/phone ... npx playwright test --config playwright.demo.config.ts финал-короткие -g телефон
DEMO_OUT=/tmp/arm112-demo/admin ... npx playwright test --config playwright.demo.config.ts финал-короткие -g администратор
```

Диктор — голос `narrator` общего сервера голоса (:8092), реплики старшего
бригады и начальника — голоса `brigade` и `chief`; переозвучки нет.
Ожидание входящего от бригады помечено плашкой «ускорено ×3» и сжато
при сборке. Сломанная сцена не валит запись: остальные снимаются,
ошибка — в вывод прогона.
